# 2.0 (2026-11-26)

The first major version. 2.0 is the 1.9 toolkit after a full regression and edge-case pass, together with the two tools added since: **Backup Script Builder 1.5** and **7z-Encryptor 1.1**. Nothing was removed, and every tool keeps working the way it did in 1.9.

## Fixed

**Folders with `[ ]` in their name (S3).** PowerShell reads `[ ]` in a `-Path` as a wildcard, so a file in such a folder "does not exist" and cannot be written. Every affected call now uses `-LiteralPath`. Before:
- **WinSuperTool and WinRepairTool**, extracted to a folder like `C:\Tools [2026]`: remembered mounts were never saved or loaded, and the BCD backup folder was not found by the restore dialog.
- **WinSuperTool Collect logs and Collect-Logs**, with an output folder like `D:\Logs [PC1]`: the summary files (`systeminfo.txt`, `hotfixes.txt`, `dism_packages.txt`, crash events, reliability history, the collection summary) were not written and were counted as failures.
- **WinFixKit**, with a data folder that has `[ ]`: the session log stayed empty, and **Save output as report** and the driver list report failed.
- **Backup Script Builder**: see [BackupScriptBuilder-1.5.md](BackupScriptBuilder-1.5.md).

Paths with `[ ]` from a file dialog, and launching the tools from such a folder, already worked.

**7-Zip zip passwords (S3):** both 7-Zip tools now refuse a non-English password for zip before starting, instead of 7-Zip failing with "The parameter is incorrect" ([7z-Encryptor-1.1.md](7z-Encryptor-1.1.md), [BackupScriptBuilder-1.5.md](BackupScriptBuilder-1.5.md)).

**Smaller:** the 7-Zip / Robocopy / Xcopy process handles of both 7-Zip tools are always released.

## Also in 2.0

- **Version numbers:** WinSuperTool, WinSuperTool-NoAI, WinRepairTool, WinFixKit, Collect-Logs, Monitor-Logs, ClaudeLogAnalyzer and their launchers say `Version 2.0`. Backup Script Builder is 1.5 and 7z-Encryptor is 1.1, each with its own version as before.
- **Release zips:** `build/Build-ReleaseZips.ps1` now also builds `7z-Encryptor-v<x>.zip`. The Backup Script Builder read-me says what needs FreeFileSync or 7-Zip and what needs nothing extra (it said FreeFileSync for everything).
- **Bug and discussion forms:** 7z-Encryptor is in the Tool list, and the version list has 2.0.
- **Tests:** a stale test that looked for the removed `Start-ClaudeLogAnalyzer.bat` now checks the current launchers. New tests check that the tools' own files are written with `-LiteralPath` and show why, with a real `[ ]` folder.

## How it was checked

- **Static analysis:** PSScriptAnalyzer on every tool. It found nothing new: the remaining warnings are deliberate empty `catch { }` blocks and unused event-handler parameters.
- **AI review:** a local model reviewed 7z-Encryptor for edge cases. Every finding was checked by hand. One was valid (the process handle, fixed above). The rest were false alarms; for example, it assumed 7-Zip is started through `cmd.exe`, which it is not. Its review of Backup Script Builder got stuck repeating one sentence and was stopped, so that tool was checked by real runs instead (next point).
- **Real runs:**
  - The `[ ]` folder behaviour.
  - 7-Zip with 7 kinds of difficult passwords in 7z and zip, opened afterwards with Windows' own `tar.exe`.
  - Backup Script Builder's Robocopy and Xcopy scripts (`.bat` and `.ps1`) and its Manual Backup scripts, run for real from a folder named `100% & fun! [x]` (with a file named `b %PATH% !x!.txt`) into destinations with `%` in the name. Every script copied every file.
- **Tests:** all Pester unit tests, and the Backup Script Builder and 7z-Encryptor window checks with real 7-Zip.

**Not checked in 2.0:** the elevated and WinPE test runs (Hiren's PE, the WinFixKit Automation run as administrator) were not repeated. The fixes in 2.0 do not touch those paths, and the 1.9 results stand.
