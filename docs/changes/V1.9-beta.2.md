## 1. Live Monitor check, and the beta 1 summaries rechecked

`tests/Run-MonitorLive.ps1` opens every Live Monitor item exactly as the tool does, in hidden windows. It checks each one starts, shows its log and reports no error.

It then proves each window type follows new activity:
- a line appended to a file;
- a filtered line, where the non-matching line must stay hidden;
- a new event in Event Viewer, where the event-ID filter must hide other IDs;
- a new file in a watched folder;
- a pasted path that only appears after its window opened.

Found and fixed:

| Sev | Fix |
|---|---|
| S3 | **"Event: Delivery Optimization/Operational" does not exist on newer Windows 11.** The window only said "Cannot open event log". Now an event log that is not on this PC is **greyed out** in the list, marked "(not on this PC)", and skipped by the per-task monitors. If one is opened anyway, it explains that event logs differ between Windows versions. |
| S2 | **Summaries, Automation and the AI phone login could stop working because of an unrelated startup error.** The window's shared timer was started as the last step of startup, so any earlier failure (seen: diskpart without admin rights) meant it never started. It now starts first. |

New in the list: **Windows Defender/Operational** under Event Viewer (live).

## 2. New tab: 9. System Info

Each button opens an easy-to-read window: headings, aligned values, and green / red / orange for good / bad / attention. Every window has **Copy all** and **Save as...**. Nothing is changed on the PC.

| Button | Shows |
|---|---|
| Wi-Fi networks and passwords | Every saved network with its **password**, security type and auto-connect setting, the one **connected now**, and the networks in range. Read with `netsh wlan export profile key=clear` into an admin-only temp folder that is deleted straight away. |
| Windows version and product keys | Edition (corrected to "Windows 11", which the registry still calls "Windows 10"), **release (e.g. 24H2)**, **full version** (e.g. 10.0.26100.2033), install date. Also: the **installed key** (decoded from the registry), the **motherboard / firmware key** (OA3), **activation** status and channel, PC / motherboard / BIOS, boot mode and Secure Boot. |
| Network connections (IP, MAC) | Every adapter, **connected first**, in route order, with the one used for internet marked. For each: type (Wi-Fi / Ethernet / Bluetooth / virtual / VPN), MAC, link speed, driver, IPv4 with subnet mask, IPv6, gateway, DNS, DHCP server and lease, network profile, metric, and the Wi-Fi details (SSID, signal, band, channel...). |
| Bluetooth devices | The adapter (status, driver, MAC) and every paired device with its **MAC address**, connected ones first, Classic or LE. |
| Video cards and drivers | Each card with driver version and date, maker, **real video memory** (from the driver's registry entry; WMI caps at 4 GB), resolution and refresh rate. Also the connected monitors. |
| Audio devices and drivers | Speakers / headphones and microphones, with the **DEFAULT** device and the default for calls marked (read with the Windows Core Audio API). Also the disabled or unplugged ones, and the sound hardware with **driver versions**. |
| Everything in one report | All of the above in one window. |

There are also **42 buttons for built-in Windows tools**, each greyed out when it is not part of this Windows edition (gpedit and lusrmgr are not on Home, for example):
- dxdiag, System Information (msinfo32), Event Viewer, Advanced System Settings, Internet Options;
- Group Policy Editor, Registry Editor, Device Manager, Disk Management, Computer Management, Services;
- Task Manager, Resource Monitor, Performance Monitor, Reliability Monitor, msconfig, Task Scheduler;
- Control Panel, Programs and Features, Network Connections, Sound, Power Options, System Properties, Environment Variables;
- Firewall, Windows Security, Local Users and Groups, Local Security Policy, Credential Manager, Certificates, Shared Folders, Print Management;
- Windows Features, Disk Cleanup, Optimize Drives, System Restore, Memory Diagnostic;
- Windows Update and About in Settings, winver, and Command Prompt / PowerShell as admin.

## 3. New tab: 10. Automation

Queue up to **10 tasks** and run them one after another on the running Windows:
- add tasks from the list (double-click or **Add >**);
- set the order with **Move up / Move down**, or use **Remove** and **Clear**;
- or load a **preset**.

The queue and options are remembered (`WinSuperTool-Data\automation.json`).

| Task | What it runs |
|---|---|
| Create a system restore point | `Checkpoint-Computer`. The 24-hour limit is lifted for this one and put back afterwards. The option "Turn on System Protection if it is off" can enable it first. |
| SFC: scan only / scan and repair / **scan, repair only if corruption is found** | `sfc /verifyonly`, `sfc /scannow`. The last one adds `sfc /scannow` only when the scan finds corruption. |
| DISM: check health / scan health / **scan, repair only if corruption is found** / restore health / clean up | `dism /online /cleanup-image ...`. The conditional one adds `/restorehealth` only when the scan says the store is repairable. |
| Check disk: read-only scan | `chkdsk C: /scan` |
| Windows Update: check (list only) / download and install | Windows Update API. Updates that need you to click something are skipped. It reports each update installed or failed, and whether a restart is required. |
| winget: list available upgrades / upgrade all apps | `winget upgrade` / `winget upgrade --all --silent` (agreements accepted) |
| Microsoft Defender: update + quick scan | `Update-MpSignature`, `Start-MpScan -ScanType QuickScan`, then the threats found by this scan |

How a run works:
- **Each task gets its own window.** It shows the live output and closes 15 seconds after the task ends.
- **Each task gets a pass / fail result**, quoting the task's own message, through the same summary engine as the Recovery tab.
- **"Pop up a summary after each task"** (on by default) shows each task's summary without stopping the queue.
- **A final summary** lists every task with its result, quote and run time. It says whether **a restart is needed**: Windows servicing, Windows Update or pending file renames. It is saved to `WinSuperTool-Data\Task-Results`.

Options:
- **Stop the queue if a task does not pass**
- **Open live log windows for each task**
- **Stop after this task**

Presets:

| Preset | Tasks |
|---|---|
| Health check (scans only, changes nothing) | DISM check, SFC scan, chkdsk scan, Windows Update check, winget list |
| Repair Windows | Restore point, DISM scan + repair if needed, SFC scan and repair, chkdsk scan |
| Update everything | Restore point, Windows Update install, winget upgrade all, Defender scan |
| Full maintenance | Restore point, DISM and SFC "repair only if needed", Windows Update, winget, Defender, component clean-up |

Bugs that the tests caught before release, all fixed:

| Sev | Bug |
|---|---|
| S2 | **The Windows Update task never saved its result.** The task window keeps its result-file path in a variable, and the Windows Update script used the same name (`$res`) for the search result, so the path was overwritten. The window's own variables are now all named `$Wst...`. The Defender script's `$t0` (the start time) is renamed too. A unit test now checks that no task script uses those names. |
| S3 | **"No video card information"**, and audio drivers shown without a version. When WMI returns exactly one object, `.Count` on it is empty in PowerShell 5.1. Every WMI result is now wrapped in `@()`. |
| S3 | **The product key was decoded wrongly** (`HVK7J-GPHTM-...` instead of `VK7JG-NPHTM-...`). PowerShell's `/` keeps the fraction, but the algorithm needs whole-number division. It now matches the key the licensing service stores. |
| S3 | The video driver's maker was missing: the access-denied error on the protected "Properties" subkey cancelled the whole registry read. |
| S3 | The System Info buttons were built from a nested list that PowerShell flattened. |
| S4 | **Summary windows hidden behind task windows.** The final Automation summary opened behind the task windows that were still counting down; it now opens on top. The per-task pop-ups stay on top in the bottom-right corner. |
| S4 | The winget quote ran its whole table into one "sentence" (winget prints no full stops). Long hits now quote just the matching line ("3 upgrades available."). |
| S4 | Virtual display adapters report "1 Hz"; refresh rates of 1 Hz or less are no longer shown. |
