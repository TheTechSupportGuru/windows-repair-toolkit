# V1.9 beta 5 (2026-11-20): resize fixes from 1.8.4

> [!NOTE]
> Draft. Not released until it has been tested on a real 4K monitor. The plan is in [docs/testing/resize-4k-test-plan.md](../testing/resize-4k-test-plan.md).

Beta 5 has the same window fixes as [1.8.4](V1.8.4.md):

- The window follows screen changes while it is open (resolution, docking, another monitor).
- On a screen smaller than the smallest usable layout, the window scrolls instead of squeezing its controls.
- Hard minimum sizes: the main window stops at 700x520, the report windows at 420x300, the Automation summary at 560x420.

- A window across two monitors stays there, and a minimized start no longer hides the main window (also from 1.8.4).

Found by the new two-monitor test ([results](../testing/TEST-RESULTS-multimonitor.md)) and fixed:

| Sev | Fix |
|---|---|
| S3 | **System Info > Video shows every display.** A new "Displays" part lists each monitor with its resolution, refresh rate, scaling and where it is (for example "right of the main display"). Before, only the main display's resolution was shown, and a second monitor did not appear at all. |
| S3 | **Automation task summaries open on the monitor the tool is on.** Before, they always opened on the main monitor. |
| S4 | **The HTML Automation report fits a phone screen.** The summary table scrolls on its own instead of the whole page scrolling sideways. |
| S4 | **System Info, Everything in one report:** the Wi-Fi notes have their own heading (one read as part of the Bluetooth part), and the network part starts with "Network summary". |

## New: Automation in WinPE (offline Windows)

Until now the Automation tab was switched off in WinPE. In beta 5 it works there on the **Target Windows** chosen at the top, which is not running:

- Only tasks that work on an offline Windows can be queued: SFC scan and repair, DISM check / scan / restore health / component cleanup, chkdsk scan. They use the same offline commands as the Recovery tab (`sfc /offbootdir /offwindir`, `dism /image: ... /scratchdir`, chkdsk on that drive).
- New task **Check disk and REPAIR (WinPE only: chkdsk /f)**: in WinPE the drive is not in use, so the repair runs straight away (on the running Windows the Recovery tab schedules it for the next restart instead).
- Restore point, Windows Update, winget and Defender need the running Windows: they cannot be added in WinPE, a queue that holds one is not started (the tool lists them and says why), presets leave them out with a note. New preset **Offline repair (WinPE)**.
- "Repair only if needed" works offline too. The summary and the HTML report name the offline Windows instead of the PC; the restart check is left out (it would read WinPE's own registry).
- Hiren's BootCD PE 10 and PE 11 (PowerShell 7 and 5.1): every offline check, repair and option passed on a real offline Windows 10. "Check disk and REPAIR" warns before it starts when WinSuperTool's own data folder is on the drive it needs to itself.
