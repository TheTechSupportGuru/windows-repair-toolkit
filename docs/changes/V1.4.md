## Changes

| # | Sev | Change |
|---|---|---|
| 25 | S3 | New `Test-IsMsr`: **Mount refuses the Microsoft Reserved (MSR) partition** in both Storage and diskpart mode, before anything is assigned. It checks the GPT type `e3c9e316-…`, which is language-independent. Previously Storage mode gave it a letter, and Explorer then offered to format it. |
| 26 | S2 | New `Get-LetterPartition`: drive letter → volume GUID (`mountvol X: /L`) → the partition whose `AccessPaths` contain it. **`Get-Partition` doesn't report letters assigned by diskpart, not even in a new process**, so V1.2/V1.3 forgot every diskpart-mode mount when the tool restarted. `Test-MountStillOurs` uses the new lookup. `Unmount-Letter` (Storage mode) uses it too, and falls back to `mountvol X: /D` when the Storage cmdlets can't see the letter. New `Sync-StorageCache` refreshes the Storage cache before lookups. |
| 27 | S4 | `Dismount-One` refuses an entry without a valid drive letter. Previously it logged "Unmounted :" and reported success. |
| 28 | **S1** | **BCD restore safety.** (a) `Invoke-Bcd` detects when a failed live command has **closed the system store** (`HKLM\BCD00000000` gone). It then shows a clear "restart required" message and **blocks every later BCD action** until Windows restarts; before, they all failed silently. (b) New `Restore-BcdBackup`: for an **offline** store (WinPE, another drive) the restore is a **verified file copy** (hash checked, hidden+system attributes kept). For the running Windows it still uses `bcdedit /import`, but only after a warning (No is the default) explaining that this fails on some UEFI firmware, as seen on VirtualBox, and that WinPE is the reliable way. |
| 29 | S3 | Sysprep pre-flight Store-app check: if `Get-AppxProvisionedPackage` is denied (it is on this build, even as admin), it falls back to the **AppxAllUserStore** registry list, which is language-independent. If neither works, it reports a **WARN** with what to look for in `setupact.log`, instead of a quiet "INFO: skipped". |
| 30 | S2 | **Regression from V1.2 fix #4.** For offline stores, `Backup-Bcd` ran `bcdedit /store X /export Y`, which bcdedit rejects ("The store export command is invalid"). V1.2 correctly refuses any BCD change without a backup, so **in WinPE every Safe Mode / boot-menu / BCD change was blocked**. In V1.1 the backup failed silently and the change went ahead without a backup. Offline stores are now backed up by **file copy**; the running system still uses `/export`. |

## Verification (2026-11-19)
- **Unit tests: 222/222 pass.** New tests: U16 covers offline restore by copy with hidden+system attributes, a missing backup, closed-store detection blocking later commands, and offline `Backup-Bcd` copying without calling bcdedit. U17 covers `Test-IsMsr` on the real disk, MSR refused before any assign, and empty letter refused. Both run for WinSuperTool and WinRepairTool.
- **Admin run on the real system** ([Tests/Run-V14-Verify.ps1](../../tests/Run-V14-Verify.ps1)): every V1.4 check passes.
  - #26: a diskpart mount of the ESP is remembered in the same process and after a restart, and a Storage-mode unmount works. V1.3 fails all three in the same run.
  - #25: MSR refused in both modes, with no letter assigned.
  - #27: empty letter refused.
  - #30: the evidence check shows `/store`+`/export` is rejected by bcdedit.
  - #28: a damaged **copy** of the BCD was restored from a backup by file copy; it was verified identical and opens in bcdedit.
  - #29: the pre-flight now reports 4 per-user-only apps, including the Claude desktop app.
  - The live BCD was unchanged, and only C:/D: have letters at the end.
- Parser: 0 errors. PSScriptAnalyzer: 0 errors.
- **Not verified:**
  - A live `bcdedit /import`. It would close the store again on this VM and need a reboot; the new detection is covered by unit tests.
  - Real WinPE.
  - Whether the 4 apps flagged by #29 would really make generalize fail.
