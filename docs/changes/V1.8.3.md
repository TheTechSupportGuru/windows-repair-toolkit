# V1.8.3 (2026-11-20): hotfix - four tools closed by themselves after starting

> [!IMPORTANT]
> **If you use 1.8.1 or 1.8.2, update.** In those versions **Collect-Logs, Monitor-Logs, WinFixKit and ClaudeLogAnalyzer** closed by themselves 1-2 seconds after starting. WinSuperTool and WinRepairTool were not affected in practice.

| File | Status |
|---|---|
| `WinSuperTool.ps1`, `WinSuperTool-NoAI.ps1`, `WinFixKit.ps1`, `WinRepairTool-startup.ps1`, `Collect-Logs.ps1`, `Monitor-Logs.ps1`, `ClaudeLogAnalyzer.ps1` | **changed**: the shared window helpers |
| launchers | unchanged |
| `tests/Toolkit.Tests.ps1` | 1 new check (22 in total) |

| Sev | Fix |
|---|---|
| S1 | **Collect-Logs, Monitor-Logs, WinFixKit and ClaudeLogAnalyzer closed 1-2 seconds after starting.** The splash screen added in 1.8.1 is shown before the tool's main window. When the main window appeared, the splash was closed, and in WinForms, closing a window that was shown before another window's `ShowDialog` also ends that `ShowDialog`. The splash is now **hidden** instead, and closed together with the tool. |

## How it was missed, and what changed in testing

- The 1.8.1 visual tests ran each tool on a **simulated 150 % display**, where the timing hid the problem.
- At 100 %, the only screenshot that showed it was blamed on an unrelated Windows Firewall prompt.
- The bug was found during the next test pass. A new resize audit (`tests/Run-ResizeAudit.ps1`) got no results from those four tools, and that was traced to their windows closing.

Now:
- A unit test runs the real splash and window helpers and requires the main window to stay open. Run against the 1.8.2 code, the same test fails.
- Every tool was started at 100 %, unmodified apart from skipping the administrator prompt. All 9 GUI scripts (stable, beta and the no-AI editions) were still open after 10 seconds. Before the fix, Collect-Logs and Monitor-Logs had closed after 1.6 seconds.
