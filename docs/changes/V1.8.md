## WinRepairTool

WinRepairTool and WinSuperTool share about 50 functions. Where WinSuperTool's version was better, WinRepairTool now uses that exact code.

| ID | Sev | Fix |
|---|---|---|
| R1 | S2 | Closing the window while a repair console it started is still running **asks** before auto-unmounting. No is the default. |
| R2 | S2 | Unmount re-checks that the letter still belongs to the remembered partition. If another volume took it, the letter is forgotten and **nothing is unmounted**. |
| R3 | S3 | It now sees and deletes Safe Mode clones made by WinSuperTool too. Before, it couldn't, and it created duplicates. WinSuperTool already saw WinRepairTool's clones. |
| R4 | S3 | Finding the boot entry checks the **loaded** boot store first (dual boot), and only Fixed or Removable drives. |
| R5 / R11 | S3 / S4 | **Rescan keeps your choices.** Before, the boot-partition choice and the selected Windows were cleared on every refresh. |
| R6 | S3 | **The running Windows now works in the Recovery tab.** Before, sfc, DISM and the driver tools always used offline syntax (`/image:C:\`, `/offwindir`), which fails on the running Windows. On the running Windows they now use `sfc /scannow`, `dism /online` and `pnputil`. The Windows list marks it as `[RUNNING - this PC]`. |
| R7 | S3 | **Unattend deploy:** if backing up the existing answer file fails, the file is **not** overwritten. |
| R8 | S3 | Drive letters are read from diskpart by column position, so it also works in other display languages. |
| R9 | S3 | **Recovery console windows:** they now use PowerShell with every argument quoted, instead of `cmd /c ... & pause`, so `&`, `^`, `%` and `( )` in paths are safe. They show the exit code, and the tool keeps track of them for R1. |
| R12 | S4 | **Missing program:** a tool whose program isn't present (e.g. `bootrec` outside WinRE) now says "not available here" instead of failing. |
| R13 | S4 | The "RAM disk" warning on BCD backups now appears only on WinPE's RAM disk, not for every TEMP folder. |
| S7 | S3 | **Backup before rebuild:** the BCD is backed up before `bcdboot` and `bootrec /rebuildbcd`, like before every bcdedit change. |
| S8 | S3 | **Results:** quick tools (no own window) now show a result message with the exit code. Before, output only went to the log. |
| R15 | S4 | Deleting Safe Mode clones reports any that could not be deleted. |
| R16 | S4 | **Unreachable clone (both tools):** when the boot menu timeout is 0, Windows never shows the menu and the new Safe Mode entry can't be picked. After creating a clone, both tools now offer to set the timeout to 5 seconds. An explicit 0 is the only value acted on. |
| R17 | S4 | **32-bit hosts:** started from a 32-bit program, it relaunches as 64-bit PowerShell first. Before, `sysprep.exe` was "not found" because 32-bit programs see a different System32. If you cancel the UAC prompt, it now says so. |
| R18 | S4 | **"Password never expires" (both tools):** the setting runs as the new account at its first logon, and only an administrator may change it. The answer-file builder now refuses it for an account in the **Users** group, instead of building a file that silently doesn't work. |
| S16 | S4 | **BCD restore by file copy:** the hidden and system attributes are put back even when the copy fails. |

## ClaudeLogAnalyzer

The file-reading, request and pairing code is now the same as WinSuperTool's AI tab.

| ID | Sev | Fix |
|---|---|---|
| A1 | S2 | **No more frozen window:** the request runs in the **background**, the window stays usable, and there's a **Cancel** button. When the session ends, a running request is cancelled. Before, the window was frozen for up to 3 minutes. |
| A2 | S2 | **Cut-off or empty answers:** `max_tokens` is now 16000 (it was 2500). Adaptive thinking on Sonnet 5.5 counts toward the limit, so 2500 could leave no room for the answer. A cut-off answer now says so, a refusal is shown as a refusal (with its category), and an empty answer shows the stop reason. Before, all of these showed "Done". |
| AI | — | **Server-side fallback (beta, same as WinSuperTool):** the request asks the API to retry a refused request on a fallback model (`"fallbacks":"default"` with header `anthropic-beta: server-side-fallback-2026-07-01`). |
| A3 | S2 | **Big or open logs:** logs are read **tail-first**, with shared access. It no longer fails on logs Windows has open, and no longer loads whole multi-hundred-MB files (measured: +359 MB of memory before, +2 MB now on a 179 MB CBS log). |
| A4 | S2 | **Accented characters:** the reply is decoded as UTF-8. Before, PowerShell 5.1 read it as ISO-8859-1, which garbled non-ASCII text. |
| A6 | S3 | File names with `[ ]` are accepted. They used to be read as wildcards and silently ignored. |
| A7 | S3 | **Gemini blocked prompt:** it now shows the block reason. Before, it crashed with "Cannot index into a null array". |
| A8 | S3 | **Size limits and binary files:** there's a total size budget (450,000 characters of logs, 15 MB of images). Binary files are skipped: `.etl`, dumps, hives and archives, plus anything that decodes to mostly U+FFFD characters. Skipped files are listed in the prompt and in the answer box. |
| A9 | S3 | **Large images:** big screenshots are **scaled down** to JPEG instead of being refused at 5 MB, and BMP and TIFF are converted. An unreadable image is skipped instead of cancelling the request. |
| A20 | S4 | **HTTP status line:** the pairing server sends "400 Bad Request" and "404 Not Found". It used to send "400 OK". |
| S3 / S13 | S3 | **Pairing:** a client that sends data very slowly is cut off after 1.5 s. One rejected key ends the QR code, because a second try with the same one-time pad would leak information about the key. |
| A21 | S4 | **Housekeeping:** the random-number generator is disposed, and the QR image is cleared once logged in. Timer errors are shown once instead of popping up 4 times a second. |
| A22 | S4 | Only dropped **files** are accepted. Dropped text used to add empty entries. |

## Launchers

| ID | Sev | Fix |
|---|---|---|
| A10 | S3 | **`WinSuperTool.bat`, elevation from a 32-bit program:** the 32-bit launcher starts 64-bit PowerShell through `Sysnative`, and that PowerShell then starts the elevated copy. `Sysnative` doesn't exist for a 64-bit process, so elevation failed. The elevated copy now gets the `System32` path. |
| A23 | S4 | **`WinSuperTool.bat`, pasted paths:** expanding `%variables%` in a pasted path also removed `^` characters. If the expanded path doesn't exist, the path is now used exactly as pasted. |
| A24 | S4 | **The two small launchers:** they now use `setlocal`, so their variables no longer leak into the calling console. |

## Not changed
- **K16 / S12 / R10:** some long jobs (registry save, Store app scans, diskpart) still run on the window's thread. Moving them would need a bigger restructure.
- **R14:** WinRepairTool still keeps no permanent activity log (WinSuperTool has one).
