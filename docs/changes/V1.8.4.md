# V1.8.4 (2026-11-20): windows that resize cleanly from 720p to 4K

> [!NOTE]
> Draft. Not released until it has been tested on a real 4K monitor at 150 % and 200 %. The plan is in [docs/testing/resize-4k-test-plan.md](../testing/resize-4k-test-plan.md).

| File | Status |
|---|---|
| `WinSuperTool.ps1`, `WinSuperTool-NoAI.ps1`, `WinFixKit.ps1`, `WinRepairTool-startup.ps1`, `Collect-Logs.ps1`, `Monitor-Logs.ps1`, `ClaudeLogAnalyzer.ps1` | **changed**: the shared window helpers, plus the per-tool fixes below |
| launchers | unchanged |
| `tests/Run-ResizeAudit.ps1` | **new**: resizes every tool through a list of sizes and screen resolutions and reports layout problems |

| Sev | Fix |
|---|---|
| S2 | **The screen changing while a tool is open.** A different resolution, docking or undocking a laptop, or dragging the window to another monitor: once a second, each tool checks the screen it is on. Its minimum size never gets bigger than that screen. A normal (not maximized) window shrinks and moves back onto the screen. |
| S2 | **Small screens at high scaling (for example 720p at 150 %).** When the screen is smaller than a tool's smallest usable layout, the window now scrolls instead of squeezing its controls together. Squeezed controls overlapped and did not return to their places. When the screen gets big enough again, the scrolling switches off. |
| S3 | **Two monitors.** A window you put across the edge of two monitors stays there; it is only moved when part of it is on no screen (a smaller resolution, a monitor removed). Nothing is moved while a mouse button is down, so a window is never pulled away while you drag it to the other monitor. (Found with the new two-monitor test, before release.) |
| S4 | **A tool could open minimized** when it was started with a minimized start style (for example several tools started at the same moment from `WinSuperTool.bat`, which minimizes its console). The main window is now always shown normally. |
| S2 | **WinPE: WinFixKit protected only the running system's folders.** In WinPE they are on X:, so "Take ownership + reset permissions" did not refuse the offline Windows' `C:\Windows`, Program Files, Users, profiles or AppData. The same folders of every Windows installation on any drive are now protected (found by the Hiren's PE test). |
| S2 | **WinPE with PowerShell 7 only (Hiren's PE 10): task windows did not start.** WinSuperTool's task and log windows, WinRepairTool, Monitor-Logs and WinFixKit's console fixes asked for Windows PowerShell, which that PE does not have; they now use the PowerShell the tool runs in. |
| S4 | **A log Windows could not read** (seen in WinPE) stopped the AI log reader with an error; it is now reported as "could not be read here". |
| S3 | **WinSuperTool was minimized when the monitor it was on was removed** (laptop undocked, second screen switched off). Its console window was minimized in a way that also activated another window; it is now minimized without that. |
| S3 | **Hard minimum sizes.** Every window stops at a smallest size where everything still fits (it grows with the display scaling): WinSuperTool 700x520, ClaudeLogAnalyzer 700x560, Collect-Logs 640x560, Monitor-Logs 660x600, WinFixKit 900x600, WinRepairTool 600x520. Report windows stop at 420x300. |
| S3 | **Monitor-Logs:** the All / None / Launch section buttons stay on the right edge and no longer cover the section list in a narrow window. |
| S3 | **WinFixKit:** the bottom button row wraps onto a second line in a narrow window instead of cutting buttons off. |

## Testing (in a VM)

`tests/Run-ResizeAudit.ps1` starts all 9 GUI scripts (stable, beta and the no-AI editions), resizes each window, visits every tab, and checks for overlapping controls, controls cut off, text that does not fit, and windows larger than the screen.

| Check | 100 % | simulated 150 % |
|---|---|---|
| Minimum size, 1280x680, 1920x1040, 2560x1400, 3840x2006, 75 %, maximized | no issues | no issues |
| Resolution changed live: 4K, then 1280x720, then back to 4K | no issues; every window fits 720p | no issues; at 720p the windows scroll, back at 4K the scrolling switches off |
| Two monitors (to the right, and above), monitor 2 at real 150 % while open, monitor 2 switched off and on, across the edge | no issues ([results](../testing/TEST-RESULTS-multimonitor.md)) | no issues |
| Unit tests | stable 286 / 286, toolkit 22 / 22, beta 50 / 50 | |

Not testable from inside the VM (real scaling of the main monitor, which needs signing out; dragging windows with the mouse): see the [4K test plan](../testing/resize-4k-test-plan.md) and section 7 of the [two-monitor plan](../testing/TEST-PLAN-multimonitor.md).
