# V1.9 beta 4 (2026-11-20): layout fixes from a review and test pass (WinSuperTool only)

> [!WARNING]
> **This is a beta.** It is a test build of WinSuperTool only. Use it on a test machine first, and keep the stable release (now 1.8.2) for real repairs.

Beta 3 plus the fixes from a light review of the beta's newest code and a full test pass. The pass covered:
- unit tests;
- a smoke test at a simulated 150 % display, recording every window's position and every control's position;
- the elevated real-world run from beta 2.

| File | Status |
|---|---|
| `beta/WinSuperTool.ps1`, `beta/WinSuperTool-NoAI.ps1` | **changed** |

## Fixed

| Sev | Fix |
|---|---|
| S3 | **Automation tab at 150 %: "Preset" and "Save an HTML report" overlapped.** The tab's scroll size was also wrong: 950 x 188 instead of 950 x 466. Until the tab control's window exists, every tab page is a 200 x 100 placeholder, so controls anchored to its bottom were measured against that. The tab control is now created as soon as the tabs exist. Same fix as stable [1.8.2](V1.8.2.md). |
| S3 | **Windows opened partly off the screen on a scaled display**: the main window, the System Info windows and the summaries. WinForms centres a window using its size before scaling. Every window is now centred again with its final size and kept on the screen. Same as 1.8.2. |
| S4 | **Per-task Automation pop-ups could run off the screen at 150 %.** They are placed bottom-right, but their size only becomes final when they load. They are now placed again once shown. |

The review also checked the PSScriptAnalyzer findings. No new kind of finding. The only unused variable is old 1.8 code, and the unused parameters are the options object, which only the restore-point task reads.
