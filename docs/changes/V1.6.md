## Changes

| # | Sev | Where | Change |
|---|---|---|---|
| 31 | S3 | `Restore-RegBackup` (Registry Backups tab, KEY rows) | `reg.exe import` prints even its success message on stderr, which PowerShell showed as a red `NativeCommandError` block. New `ConvertTo-PlainText` turns such stderr lines into plain text. The restore is now judged by **reg.exe's exit code**: on failure it says *"FAILED … (reg.exe exit code N)"* and does **not** mark the backup as restored, so it stays the "original" and can be retried. |
| 32 | S4 | "Reset TCP/IP stack", "FULL network reset" | New `Invoke-IpReset`: runs `netsh int ip reset` and then **counts the "failed" items**. It explains that a few "failed. Access is denied." items are normal on Windows 10/11 (this VM had 1 of 34), and is honest about the log: it shows netsh's log file if one was written, otherwise says the output is kept in the session log. The help text no longer promises a log file. The FULL reset's "DONE" line points to any NOTE lines. |
| 33 | S4 | "Reset Winsock catalog", "FULL network reset" | New `Invoke-WinsockReset`: compares the Winsock **provider list** before and after `netsh winsock reset` and **names any provider that disappeared**. For RFCOMM it says this is Bluetooth serial and that devices may need re-pairing, and that the Registry Backups tab can put the old catalog back. The help text and both confirmations mention Bluetooth serial (RFCOMM). |

## Verification (2026-11-19)
- **Unit tests: 234/234 pass.** New U20 covers:
  - A successful reg import on stderr: plain text, marked restored.
  - A failed reg import: FAILED with the exit code, not marked restored.
  - A TCP/IP reset with a failed item (NOTE plus count, honest log line) and a clean reset (no NOTE).
  - A Winsock reset dropping RFCOMM (named, with the Bluetooth hint).
- **Real-system checks without admin:**
  - #31: a real `reg.exe import` restore of a HKCU test key through V1.6's `Restore-RegBackup` brought the value back, and the output is one clean "Imported …" line with no `NativeCommandError`.
  - #32: the **real** netsh output captured during the network test, fed through `Invoke-IpReset`, gives *"netsh reported 1 item(s) as failed (exit code 1) … normal …"* and *"netsh did not write its own log on this Windows build"*.
- Parser: 0 errors. PSScriptAnalyzer: 0 errors.
- **Not repeated:** a full network reset with V1.6 itself, which would need another reset plus 2 reboots. The helpers only wrap the same netsh commands that were verified in Phase 3 part 3.
