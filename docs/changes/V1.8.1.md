## Window scaling and resizing (all tools)

| Sev | Fix |
|---|---|
| S3 | **Text was blurry or cut off on 125 % / 150 % / 200 % displays.** One example was the "Run a .ps1..." button next to Rescan. PowerShell did not tell Windows it can scale, so Windows stretched each window like a picture, and the fixed pixel layout did not leave room for the larger text. Every tool now tells Windows it is DPI-aware and scales its own windows: the main window, every dialog, the summary windows and the list columns. Text is sharp and fits at any scaling. |
| S3 | **Resizing the window did nothing useful.** Making it bigger left empty space; making it smaller cut off the buttons on the right. Lists, logs and output boxes now grow with the window, and buttons on the right edge stay there. A window smaller than the layout shows scroll bars on its tabs instead of squeezing the controls. When the scaled window does not fit the screen, it opens maximized. |
| S4 | WinSuperTool's top-right buttons (Rescan, ?, Run a .ps1..., Data folder) widen themselves if their text does not fit, for example with very large fonts. |

**How this was found:** WinForms only scales what exists when scaling is switched on. Switching it on when each window is created scaled nothing inside it, so every tool now switches it on when the finished window loads. A unit test checks this with a simulated 150 % display.

**Tested:** every tool on a simulated 150 % display (every font ×1.5, every window told the display is 1.5×), at its normal size, shrunk to the minimum and maximized. Every window and control scaled by 1.5. The real 150 % / 200 % look is not tested yet, because the test VM runs at 100 %.

## Splash screen (all tools)

While a tool loads, a small window shows:

> **Windows Repair Toolkit**
> Brought to you by TheTechSupportGuru
> Licensed under GNU GPL v3.0
> *Loading <tool> ...*

It closes when the tool's window is ready, and stays at least about one second so it can be read.

## No-AI edition of WinSuperTool

For people who do not want logs sent to an AI service. `WinSuperTool-NoAI.ps1` (with `WinSuperTool-NoAI.bat`) is WinSuperTool without:
- the AI Analyze tab;
- the phone QR login and its network listener;
- the "Send key logs to AI Analyze" button;
- any code that contacts Claude or Gemini.

Everything else is identical. The tabs are renumbered 1-7, and the window title says "(no-AI edition)".

It is **generated, not maintained by hand**: the AI parts of `WinSuperTool.ps1` are marked (`#region AI-ANALYZE` blocks and lines ending in `# [AI]`), and [`build/Build-NoAIEdition.ps1`](../../build/Build-NoAIEdition.ps1) removes them. The build refuses to write the file when:
- the result does not parse;
- it still calls a removed function, or reads a variable that only the removed code set;
- it still contains AI-service or network code (API hosts, keys, TCP / HTTP listeners or clients, web requests).

A unit test rebuilds it and checks that the committed file is identical.
